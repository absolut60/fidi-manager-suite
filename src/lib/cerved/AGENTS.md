- Light Report purchase sends the POST /v1/purchase body only from acquistaLightReport, always with subject_type COMPANY (required by the Cerved "Product Purchase" sheet; every linked subject comes from entity_search COMPANIES_ONLY), so no other caller or field shape can be invented.
- Pending recovery delegates only to recuperaESalvaLightReport; the service-only blocca_report_cerved_e_notifica RPC atomically guards the 48-hour transition and notifications, receiving recipients' roles from RUOLI_AGGIORNANO_CERVED to avoid duplicate alerts or divergent permissions.
- Grading descriptions are decoded only in cerved-presentazione: C4_1 = Assenti (green); C5_1 = Assente (green), C5_2 = Alcuni segnali di rischio (amber), C5_3 = Forti segnali di rischio (red); C6_1 = Assenza di segnali di rischio (green). C3_1/C3_2/C3_3 and unknown codes stay neutral numeric /100, because their wording is not verified.
- Report reading is generated only by fixed rules and thresholds in cerved-lettura, never AI; it reads normalized Light Report fields and the existing customer exposure without changing credit decisions.
- XML GrossProfit is MOL and Ebitda is EBITDA; bank maturities and ratios are extracted separately from verified root-scoped paths, so rounded Cerved values are never reconstructed from PDF or guessed.
- Company connections are extracted only from root PositionCompany/PositionRelatedCompany (Director and RelatedCompany) by normalizzaLightReportXml; person IDs and company IDs remain separate, because identical fiscal codes/names can identify both a person and a sole trader.
- Connection wording, ordering and related negative-event aggregation live only in cerved-collegati; EndDate closes a role, cancellation limits undated roles, and explicit ActiveLink false never becomes an ongoing link. Revenue/Profit here are already euros, unlike CEBI balance thousands.
- Cerved data belongs to the subject (id_soggetto): cerved_soggetti links exactly one cliente or lead per row, and report/photo cliente_id/lead_id only record who originated them, so one purchase serves every linked record.
- One Cerved update path for cliente and lead (aggiornaCervedSoggetto); purchase guard is per id_soggetto; a new link reuses the id_soggetto of any existing link with the same VAT number before calling entitySearch; aggiornaCervedCliente/apriPdfReportCervedCliente are thin wrappers only.
- Screens read cerved_report/cerved_fotografie only by id_soggetto obtained from cerved_soggetti via cerved-letture; never by cliente_id/lead_id (those are origin only).
- SchedaCervedEntita is the only Cerved card (cliente and lead); MADE-internal parts (fido MADE, come paga MADE, confronto MADE) depend only on datiMade; trigger trg_lead_cerved_cliente copies the lead's subject link to the client on conversion when VAT matches, never purchasing again.
- Cerved list gauge for clienti and lead comes only from useEntitaConReportCerved.
- Compila da P.IVA uses only entity_search (free quota ~10,000/year, counted from cerved_chiamate); it never purchases, links or monitors.
- Light Report extraction stays in normalizzaLightReportXml with root-scoped verified paths; CEBI PD is separate from CGS, rounded thousands convert to euros without reconciling granular balances, and undecoded CgrFlags/relationship flags stay raw to avoid invented negatives.
- Cerved sheet presentation uses only normalized Light Report data when present; decoding lives in cerved-presentazione and fixed reading thresholds in cerved-lettura. Compact views retain their existing CGS resolver, so this sheet change does not alter list gauges.
- Insolvency procedures (Bankruptcy) and Conservatoria deeds (AgreedWindingUpProcedures) are classified only in normalizzaLightReportXml by SubjectReport, prejudicial type and cancellation; company flags count only own events and related-party events go to collegati/altri_soggetti, so a linked subject's event never marks the company red.
