- Supplier read/write gates: only auth_ha_accesso_fornitori/auth_puo_gestire_fornitori; articles/costs stay behind auth_consulta_preventivi (preventivi roles + store_manager read-only; UI uses puo_vedere_articoli), so menu, pages and RPCs cannot diverge.
- Supplier activities live only in attivita_fornitore: users insert/update only origine='manuale' and may delete both origins; origine='invio' rows are written server-side (service_role), keeping them apart from recovery and commercial activities.
- Supplier email bodies are sanitized only by sanificaHtmlEmailFornitore (pure allowlist in src/lib/comunicazioni-fornitore.ts, Worker-safe); the dialog reuses the shared RichTextEditor in caratteri/compatto mode, and deleting an activity removes its attachment files and rows first, so no orphan files remain.
- Supplier letters reuse the client letter engine (lettera-pdf.server creaDocumentoLettera/disegnaLettera) with the recipient passed in; editor HTML becomes PDF blocks only via lettera-blocchi, so client letters stay byte-identical (tests/fixtures copy).
- The supplier list and "select all filtered" share public._fornitori_filtrati (cerca_fornitori / cerca_fornitori_ids), so counts and selections cannot diverge.
- Multi-supplier email runs only in the Inngest job fornitori-invio-multiplo: one email per supplier from pre-created in_invio attivita_fornitore rows (unique invio_id+fornitore_id), so retries never resend; one notification at the end.
- Supplier goods/services type comes only from public.tipo_fornitore_effettivo (Gamma macro 01/03 wins, then tipo_app, then legacy manual categoria_fornitore); list, ids, detail and classifica_fornitori all use it, and classifica_fornitori never overwrites Gamma-decided rows.
- Supplier contacts share the single contatti row (fornitore_id beside cliente_id/lead_id); supplier-only contacts are excluded from marketing, WhatsApp and reconciliation in SQL, and unlinking deletes only contacts with no client/lead left.
- Supplier convention lives only in fornitori.stato_convenzione (text, CHECK-extensible; boolean convenzionato is deprecated), written only by imposta_stato_convenzione_fornitori (amministratore only, twin puoCambiareConvenzione); tipo_fornitore_effettivo treats convenzionato as merci unless Gamma macro 01/03 decides, and BandierinaConvenzionato is its only visual mark.
- Supplier list sorting is server-side only in cerca_fornitori (_ordina whitelist via static CASE, no dynamic SQL, id tiebreak; TS twin ORDINAMENTI_FORNITORI); cerca_fornitori_ids stays unsorted so selection is unaffected.
- Supplier obsolete, brand and services subcategory are decided only in SQL (fornitore_obsoleto, marca_prevalente_fornitore/ricalcola_marche_fornitori which never touches marca_fonte='manuale', sottocategoria_fornitore_effettiva: Gamma desc wins, only for tipo servizi); the UI only reads the returned fields, writes go through admin-only imposta_marca_fornitori/imposta_sottocategoria_fornitori, and the article sheet reads the computed field instead of re-deriving it.
