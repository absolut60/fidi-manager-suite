# Architecture rules

- The credit-review perimeter uses isPrivatoFido/isSedeCentraleFido and the SQL clienti-row cliente_privato_fido overload to exclude private clients and the central store before preset pagination/count/selection; the text overload remains fiscal-only. Alert reads and refresh share this perimeter, and bulk inputs exclude the central store even before recalculation, so stale published rules cannot reintroduce it.

- Official Gamma scadenziario parsing lives only in the browser-safe scadenziario-parser module; both browser staging and direct-file server entrypoints parse and resolve duplicates once before chunking, while chunk dedup remains a safety net and expected-row counters retain their existing valid-client rule.

- Alert-fidi notifications are produced only by public.invia_notifiche_alert_fidi after alert refresh; it locks eligible alerts, uses the existing grouping/push triggers and marks logical deliveries rather than INSERT RETURNING rows, because grouping may cancel inserts.

- TooltipDettaglio owns delayed tooltip mounting for recovery actions, commercial calendar events and task rows, so content and any detail queries mount only while open without changing click or touch handlers.

- FiltriCollassabili supports opt-in desktop collapse and a persistent summary; existing callers retain always-visible desktop filters to avoid regressions.
- The bulk credit-proposal dialog keeps business handlers unchanged and uses existing list cards below the desktop-table breakpoint; below sm, settings and cards share one scroll container with collapsible details, while desktop retains list-only scrolling, to keep clients reachable on iOS.

- Payment-condition display in credit-request UI must use the shared helpers and text component next to useCodiciPagamento; this keeps catalog lookup, fallback and formatting consistent without changing stored or exported values.
- FM55 publishes v2 values into fido_teorico_cliente after both block upserts; all screens and request reference amounts read this canonical table while semaforo fields and preview-only Alert access remain independent.
- "Scaduto oltre N giorni" and the 12-month real collected amount are computed only by public.scaduto_oltre_giorni (per-row, RiBa threshold, excluded codes, anticipi offset via calcola_scaduto); the zeroing rule also requires the configured share of pagato_12m, below it only the signal from public.segnalazioni_fido applies; rule scaduto_non_incassato zeroes the theoretical credit and riferimentoRichiesta skips the debt protection for it and keeps an approved extra only when public.extra_fido_protetti marks protezione_valida (scaduto already known at request creation, stored by trigger in richieste_fido.scaduto_al_momento), so decisions are respected but grown debt resets to zero.
- Request references apply fidoPropostoPerRichiesta only inside fetchFidoTeoricoPerRichiesta, using canonical esposizione_corrente without orders and the configured alert threshold; arrotondaFidoV2 mirrors SQL rounding in this same module, keeping displayed, initial and saved references consistent without altering theoretical credit calculations. Signal debt text also reads canonical exposure so pre-November rows never require guessing from fabbisogno; fido-segnalazioni keeps legacy definitions but no legacy grouping.
- riferimentoRichiesta returns published values directly for blocked/legal rules, bypassing debt and extra protections; daValutareProposta excludes all zero-to-zero renewals so counts and bulk visibility share the same decision.
- Import/Export refreshes precalculation state on completed imports observed in its existing history query; bounded automatic polling uses the shared readiness rule and never starts recalculation itself.
- Automatic recalculation readiness and missing-source labels are evaluated only by fido-teorico-import-completi; its query retains the entire local calendar day plus all processing imports so earlier same-day sources remain available after a recalculation.
- Alert-fidi request state is read live in src/lib/alert-fidi.ts (esitoRichiestaAlert, using isRichiestaAttiva), while aggiorna_alert_fidi mirrors it at refresh by linking any active request, closing only once processed and reopening on reject; this keeps the page current without waiting for recalculation.
- Margin and the informational normal threshold are computed only by public.fido_v2_margine_tetto; get_fido_teorico_v2 uses closed-calendar purchases and invoice-weighted payment terms, while the block publishes the helper outputs without capping credit or including orders. The invariant ten-argument segnalazioni_fido signature receives actual proposed credit in _valore_senza_tetto (not the stored column) to compare special profiles correctly; its deprecated seven-argument overload delegates unchanged signals and suppresses comparisons lacking that input.
- Exposure history is reconstructed only by public.esposizione_picco_cliente using Gamma payment-date events; get_fido_teorico_v2 applies its delta only as a reduction brake for standard margin profiles and the block persists the peak, preserving the existing return contract. segnalazioniCorrenti only suppresses stale oltre_normale on non-increases; SQL remains the sole code generator, so no local threshold calculation can diverge.
- Bulk-proposal type visibility and hidden-reason counters live only in proposta-fido-visibilita; active requests are always excluded before type filters and touched/mostraSempre exceptions, preventing duplicates.
- Bulk-proposal row reasons and short explanations come only from motivoRigaProposta; informational coverage reuses fidoPerTornareSottoSoglia and the existing SQL-twin arrotondaFidoV2, never changing recommendation, inclusion or submitted values. Brake explanations use the published SQL brake sentence and pre-brake helper value, not a local credit calculation.
- Bulk-proposal visibility categories are separate from submitted request types; renewal categorization and reason counts stay in proposta-fido-visibilita, using canonical red severity and alertConsumoAperto (statoEffettivoAlert) on live request-enriched alerts with giaDeciso protection. Initial inclusion stays in the same module, and shared SemaforoPallino only presents canonical materialized semaphore fields.
- Desktop tables: from 1280px every column and button fits on screen, never actions cut off on the right; merge columns, fix column widths (table-fixed), stack buttons. Applies to every new page. ("Tabelle da PC: da 1280px tutte le colonne e i bottoni stanno nello schermo, mai azioni tagliate a destra; si accorpano colonne, si fissano le larghezze, si impilano i bottoni. Vale per ogni pagina nuova.")
- "Lascia così" exists only in the bulk proposal and goes only through public.lascia_cosi_revisione; the Alert fidi page offers only "Apri proposta", and its "Fido teorico" is teoricoPropostaIniziale, the same helper that pre-fills the bulk proposal, so the two values cannot diverge. Alert consumption uses debt only (debitoOggi mirrors aggiorna_alert_fidi and consumo_perc); open orders are informational and act only as a reduction floor inside get_fido_teorico_v2's existing brake.
- Theoretical-credit recalculation steps live only in fido-teorico-ricalcolo-passi.server, shared by the Inngest job (one step per block) and the manual button (one server-function call per step); block size, statement-timeout retry of the same idempotent block and page-state resume live only in fido-teorico-ricalcolo-riprova, because block time varies with database load (measured 0.5 s to 24 s on the same block).
- service_role runs server jobs with statement_timeout 60s (theoretical-credit recalculation, imports, Inngest); authenticated users stay at 8s (authenticator 8s, anon 3s). Never call heavy RPCs from the browser as the user — they go through server functions using supabaseAdmin.
